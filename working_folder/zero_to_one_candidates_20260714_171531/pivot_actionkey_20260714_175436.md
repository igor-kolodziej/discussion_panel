# Zero-to-One Pivot: CommitKey Production-Database Relay

## Preserved Insight

Keep the separately trusted display and exact-action signed receipt outside the AI coding agent's host.

## Structural Change

Replace generic enterprise approvals and cross-vendor actions with one enforceable workflow: destructive PostgreSQL production changes initiated by AI coding/operations agents. The production database accepts privileged agent DDL/DML only through a CommitKey proxy using a dedicated mTLS role; direct agent credentials are removed. The terminal displays normalized SQL class, target database/table, row-count/diff bound, and migration hash, then signs a one-use receipt checked by the proxy immediately before execution.

## Target Niche and Buyer

Twenty- to 200-person B2B SaaS companies already using AI coding/operations agents, with PostgreSQL production databases and a CTO/platform-security owner. Avoid banks and generic Fortune 500 procurement during proof.

## Painful Event and Willingness to Pay

The event is the security decision to let an AI agent prepare or run a production migration after a destructive near miss, customer security review, or internal access-control change. A single mistaken `DROP`, unbounded `DELETE/UPDATE`, privilege grant, or wrong-database migration can cause outage, restore work, breach exposure and customer loss. Hypothesis: 12–25k PLN paid pilot and 36–72k PLN annual service is within a platform/security budget.

## Value and Profit Wedge

One self-hostable PostgreSQL proxy, one terminal and four destructive action classes. No consulting or general agent governance. A canonical parser and database-side role policy make bypass technically testable. Expected direct pilot cost is under 6k PLN and software-led gross margin exceeds 70% if deployments stay standardized.

## Domination Wedge

Own “AI-agent destructive PostgreSQL change approval” for small security-conscious SaaS teams before expanding. GitHub-native installation, database-side enforcement and a verifiable red-team harness offer a narrower, cheaper wedge than enterprise PAM.

## Acquisition Channel

First 10: maintainers/users of public AI coding-agent tools, PostgreSQL/SaaS security communities, recent public AI-agent adopters, and founder-led technical content demonstrating an altered SQL/wrong-database attack. First 100: open-source proxy adoption, security consultancies and PostgreSQL managed-service marketplaces; no partner is needed for the first paid pilot.

## Primary Control Point

The customer contract and architecture route every covered agent-originated privileged database write through the CommitKey proxy. The database holds no equivalent agent credential; the proxy's mTLS role, issuer keys, canonical SQL/migration schema, terminal firmware and signed receipt registry are owned and deployed at first sale.

## Cold Start and Resource Bootstrap

Month 1: software proxy, local PostgreSQL lab, parser, one secure-element/e-ink terminal and bypass tests under 15k PLN. Months 2–3: open-source read-only simulator and a working destructive-action attack demo. Months 4–6: approach 100 named 20–200-person SaaS/platform teams for a prepaid 12–25k PLN pilot. Maximum pre-proof spend 25k PLN. Month 12 proof under 90k PLN is two unrelated paid customers, two agent tools, independent penetration review and one contracted renewal.

## Expansion Path

After repeatable PostgreSQL demand: managed PostgreSQL services, MySQL, cloud IAM changes, Kubernetes production mutations and CI/CD release gates. Each new action class must preserve database/resource-side receipt enforcement rather than become a generic approval UI.

## Minimum People Stack

Founder owns product, agent integrations, canonicalization tests, analytics and sales; fixed-scope PostgreSQL/security engineer and penetration tester. No production hardware tooling before paid proof.

## Principal Risk

Database vendors, PAM companies or open-source projects add adequate signed approvals; smaller SaaS teams may simply prohibit agent execution or accept software pull-request review, eliminating hardware WTP.

## First Disconfirming Test

Give the working attack/bypass demo and architecture to 100 qualified SaaS platform owners. Kill if none prepays, if most will not allow any agent production credential, or if ordinary Git/CI approval is judged equivalent.

## Evidence Preserved

NIST/Microsoft agent-security concern, FIDO exact-transaction precedent, and the panel's conditional Tier 1 verdict for a truly routed transaction.

## New Hypotheses

The named SaaS segment is reachable within 180 days; PostgreSQL enforcement closes bypass paths; buyers prefer a physical trust surface to Git/CI software approval; 300 accounts at roughly 60k PLN annual value can support founder wealth.

## Why This Is Not the Original Failure Shape

It changes the generic CISO buyer to a small SaaS CTO/platform owner, names destructive PostgreSQL changes as the paid event, removes cross-vendor breadth, replaces abstract routing with a database role that accepts privileged agent writes only through the proxy, reduces pre-proof spend, and uses open-source technical distribution rather than enterprise status sales.
