## Internal Cap Check

- Concrete 6-month control proof exists: owner-signed data/export mandate, site/charger inventory, old operator/backend request, OCPP/config/session/payout export, new-CPO acceptance, and first migrated chargers or written no-go.
- The first proof is cash/revenue control: site exits a bad operator, gets session/payout truth, migrates chargers to a new operator, or proves why migration cannot happen.
- Data Act timing is current and creates a new pressure on connected-device data holders, but the startup should not present legal advice or enforcement.
- Copy risk is meaningful: new CPOs, installers, backend providers, and EV consultants can copy the workflow. The wedge is strongest because the old CPO/backend has a conflict, while the new CPO often wants the site but not the messy exit file.
- Technical scope is a risk. The product must stop at data/config/export/migration handoff and use EVSE/OCPP contractors for technical checks. It must reject broken chargers, electrical defects, payment-terminal failures, UDT/metrology problems, and warranty disputes.
- This is materially different from failed EVCharge commissioning: no promise to make a broken site work; the controlled object is the owner-authorized exit file and payment/session stream.
- This is materially different from failed EV Battery Data Release: it does not certify vehicle battery condition; it unlocks a site-account/operator switch and current charging revenue.
- It is adjacent to the confirmed Data Act Machine Data Liberation Desk but uses a different control point, buyer trigger, payment event, and proof artifact: EVSE operator switching and charging revenue, not compressed-air telemetry for savings memos.
