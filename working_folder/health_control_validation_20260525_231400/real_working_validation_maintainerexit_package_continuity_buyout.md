## Validator Summary

## Strongest Objections

1. Free-riding may kill conversion because many companies can keep using the package without paying.
2. HeroDevs, Tidelift, Snyk, GitHub, foundations, dev agencies, and security firms already serve adjacent open-source continuity and supply-chain needs.
3. Maintainer authority may be messy across GitHub, registry publishing, contributors, old employers, trademarks, docs domains, release keys, and licenses.
4. A package maintainer takeover is itself a supply-chain trust event, especially from an unknown founder.
5. Code quality may be weak: stale dependencies, poor tests, fragile CI, bad release process, and hidden security debt can turn the package into a maintenance trap.
6. Companies may fork, pin, vendor, rewrite, or migrate instead of paying.
7. Community backlash can damage the controlled asset if the handoff looks like enclosure rather than continuity.
8. Support scope can sprawl into integration debugging, feature requests, old-version support, private patches, SLAs, procurement documents, and vulnerability triage.

## Useful Narrowing

The evaluator's best version is:

**Official continuity handoff for small production-relevant OSS packages with paying B2B dependents.**

It would require:

- one package with clean maintainer authority, tests, CI, registry access, and visible production dependents;
- maintainer option before announcement;
- meaningful seller cash only after dependent-company prepayments;
- eight dependent companies paying at least 60,000 PLN total before close;
- senior software/security review of release process and maintenance scope;
- one transparent low-risk maintenance, compatibility, or security release.

The validator said to kill the model if serious production-user conversion is below 5-10%.

## Search Lesson

Exact namespace/release control is stronger than ordinary service work, but it is not enough when the buyer can free-ride or fork and when the founder becomes a supply-chain trust risk. Future candidates need a controlled payment stream or asset where the customer cannot easily benefit without paying and where control itself does not introduce new trust anxiety.
