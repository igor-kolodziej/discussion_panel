# Zero-to-One Evaluation: GitHub Workflow Sentinel v1

## Diagnosis

Workflow Sentinel uses a formal GitHub App transfer and a B2B payer, which is directionally stronger than buying source code. It nevertheless depends on an unidentified seller, unverified continuity of Marketplace subscriptions, and a release-evidence feature that GitHub rulesets, audit logs or open-source Actions can absorb. The expected model needs more than 200 gross additions from a 20-customer starting cohort without a demonstrated acquisition channel. The app transfer is a mechanism, not a differentiated business.

The user-defined revenue-quality gate replaces the original Founder Wealth Gate for this evaluation.

## Evidence and Assumptions

- Sourced: GitHub permits transfer of a GitHub App registration; GitHub Marketplace can sell paid app subscriptions.
- Unproved: public app-for-sale supply, price, continuous paid subscriptions, active installs, retention and seller willingness.
- Candidate claim: organisations will pay 5,000–15,000 PLN annually for a signed policy/exception record.
- Missing: one target, three plausible sellers, customer interviews, proof that GitHub-native features do not satisfy the outcome, permission/security cost, price, CAC and support burden.

## Overall Score

**48/100 advisory**. Weighted total: `96 ÷ 20 × 10 = 48`. This is not a validation score.

## Control Point

**Tier 3 now; conditional Tier 1 after transfer.** The GitHub App registration and installations could be owned, but subscription continuity has not been shown. The strongest copy risk is GitHub shipping the evidence workflow within native rulesets/audit logs, followed by an open-source Action implementation.

## Founder Wealth Gate / User-Defined Revenue Quality Gate

**Fail.** Conservative is 350,000 PLN. Expected reaches exactly 1,000,000 PLN at 30% margin, but requires an unidentified 20-customer acquisition followed by a roughly tenfold net expansion and more than 200 gross additions. Price and churn are not evidenced. Strong is speculative.

## Reachability Gate

**Fail.** There is no exact seller, purchase price, cohort or confirmed subscription transfer. The founder cannot credibly close, ship and collect six qualifying payments within 180 days under 40,000 PLN based on current evidence.

## Expansion Check

The release-policy beachhead is narrow, but GitHub already owns the underlying workflow and can integrate adjacent controls. Cross-platform expansion adds adapters and sales burden before proving the first product. No local advantage exists.

## Fatal Objections

1. No affordable seller pool or exact target.
2. No proof that registration transfer preserves the complete paid Marketplace position.
3. Native GitHub and open-source copy risk attacks the core paid outcome.
4. The 20-to-200 customer bridge has no distribution or CAC evidence.

## Strongest Salvageable Insight

An installed B2B app registration with recurring billing is a better seed asset than code, provided subscription continuity and a non-native workflow are proved.

## Recommendation

kill
