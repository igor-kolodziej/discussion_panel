## Search Frame

Round 166 proved that hard asset control fails when the market is already professionalized around the exact transaction. This round searches for a live B2B SaaS buyer gate where the founder can produce an operational release artifact or technical correction, but only when a named deal is blocked.

Current source checks:

- Microsoft Learn confirms publisher verification is primarily for developers building multitenant OAuth/OIDC apps and that unverified-publisher warnings appear in consent screens.
- Microsoft Learn says admins can configure tenants so apps not from verified publishers require admin consent.
- Microsoft Graph permissions documentation confirms many permissions require admin consent and that least-privilege permission requests are a best practice.

The lead candidate is an enterprise buyer-consent release desk for small B2B SaaS vendors whose Microsoft Entra/OAuth/Graph integration is blocked by unverified publisher, missing publisher domain, broad Graph scopes, missing admin-consent packet, or buyer security policy.

## Lead Candidate

**ConsentGate Entra App-Consent Release**

### Internal Simulated Score

88 / 100

### Why It Clears Simulation

- The trigger is a named enterprise buyer that cannot approve a SaaS integration, not generic readiness.
- The founder can touch a concrete technical control surface: app registration, publisher domain, verified publisher prerequisites, requested Graph scopes, consent screen, redirect URIs, tenant settings evidence, and least-privilege scope map.
- The proof is buyer/admin progress: verified publisher badge, reduced risky scopes, admin-consent packet accepted for review, admin consent granted, pilot unblocked, or clean no-go because the app needs high-risk scopes/security work.
- The value is tied to a deal, renewal, pilot, or deployment blocked by Microsoft tenant policy.
- It avoids formal certification, legal advice, and broad security remediation.

### Internal Objections

- Microsoft partners, identity consultants, appsec firms, and competent SaaS developers can copy the workflow.
- Some cases require real product engineering, security architecture changes, or partner-program verification outside a 7-day sprint.
- Buyer tenant admins remain in control of final consent.
- A founder must avoid helping apps request excessive Graph permissions or bypassing tenant security policies.
- The market may be smaller than the prompt implies unless many B2B SaaS vendors hit enterprise Microsoft consent blockers.

### Gate Decision

Advance to working Zero To One validation because the simulated score is strictly above 87 and the control point is a live app-registration/admin-consent blocker tied to a named enterprise deal.
