## Selected Candidate

**MCPToolFence Buyer Action Release Sprint**

### Why It Advances

This is not a generic AI security audit or AI questionnaire response. The accepted case starts only when an enterprise buyer, security team, procurement team, or implementation owner has a written blocker tied to a tool-using agent or MCP integration. The hard artifact is a sandboxed trace bundle showing what the agent can and cannot do through named tools, scoped credentials, allowlists, human approvals, audit logs, and prompt-injection/tool-poisoning probes.

The candidate is still risky because it sits near the failed AI security branch. It clears the simulated gate only because the buyer fear is more concrete than RAG source quality: the AI can call tools that read, write, send, create, delete, or trigger workflows. If the evaluator treats this as another appsec service or says appsec incumbents can easily absorb it, the branch should be killed.

### 60-Day Proof Required

- Three appsec, SOC2, fractional-CISO, or AI implementation partners sign routing terms, or six direct vendors prepay.
- Six live buyer-action blockers are prepaid or partner-guaranteed at 20,000-60,000 PLN.
- Every case includes written buyer condition text, named deal/go-live/renewal/payment consequence, authorized sandbox, tool catalog, credential/permission map, and logging access.
- Four cases produce buyer-progress outcome, narrowed go-live scope, approved manual-gate condition, accepted no-go, or remediation handoff.
- At least two cases produce buyer response to the tool-action evidence bundle, not only internal delivery.
- Gross margin remains above 60% after AI security reviewer cost.
